Implementing reassigned spectrogram

Started 20250814

Continued 20251129

Time-frequency reassignment is a method of correcting the vertical and horizontal positions of points on a time-frequency grid of a generic short-time Fourier transform. In simple words, on a reassigned spectrogram you will see a straight line from a pure tone, instead of a «sausage» where center of it is a desired frequency.

You can find it in some quality spectrum analyzers. For example Wave Candy in FL Studio uses it in it's «Enhanced frequency» mode. Also Visu and MiniMeters are using this method to enhance resolution. Though I think Wave Candy uses the phase information directly to do it's corrections (like a phase vocoder), which does not require even using more than one FFT.

The method itself is really simple. You just use two more FFTs with two different windows on an original audio frame you took for an analysis, do some complex divisions and there you are. The formulas in Fitz & Fullop are needlessly expanded from their simple complex forms, and if your language supports complex math you can just use them directly from the referenced Auger & Flandrin paper:

$$\delta_t = -\mathrm{Im}\left({X_d \over X}\right) $$

$$\delta_\omega = \mathrm{Re}\left({X_t \over X}\right) $$

Except in practice, time displacement must be divided by 2π, and multiplier in time window \(\left(X_t\right)\) is given in samples if you're multiplied the time ramp by nfft as described in papers. You can also multiply the time ramp by overlap factor instead of nfft and the reassigned time will be in frames.

  • Time displacement must be divided by 2×pi. If you haven't got it working, that's why.
  • Multiplier in time window is the time scale. If you're using window size it will be in samples. You can also use overlap factor so reassigned time scale will be in frames.
  • Formulas for implementing TFR with “flattened” complex math.
  • TFR is invertible if you are using it to derive some mask. Just remember original bin time-frequency coordinates for each point. This property can be used for source separation purposes, for example. One probably can derive a HTDemucs-like architecture, but instead of double time-frequency domain processing make it «glow» only certain points for each of the source types.
